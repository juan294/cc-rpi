[Main plan](../2026-09-05-cc-rpi-v2.md). This is the complete disposition of all 57 grouped observations from the local audit catalogue, `docs/research/2026-09-05-code-skills-agents-catalogue.md`. That ignored evidence file is not a dependency of the published plan. Observations overlap and are not 57 separate features. Phase 6 verifies the required work across the final candidate.

- **C**: required canonical/self-application repair or distribution capability in v2.0.
- **M**: adopter reconciliation represented by a fixture and migration guidance; actual application to a selected project is later authorized work.
- **E**: optional measured experiment. Existing owner defaults remain; the experiment is not a release blocker.
- **X**: external project, vendor or staged content outside exported cc-rpi ownership. Preserve an explicit follow-up, without editing that project here.

Mixed labels distinguish canonical prevention from later project repair. M/X completion for this release means the fixture or precise handoff exists, not that the actual project was fixed. The externally removed L'Ayalga worktree is an unavailable audit snapshot, not an installation to recreate. D13's missing optional catalog applies specifically to Chapa CLI.

The phase contracts govern if an earlier audit proposed changing owner philosophy: dynamic assignments within a phase are required; separate phase conversations, TDD, complete phase/final gates, and fix-all remain the default. Pure model-native retirement and weaker human gates are deferred. All meaningful changes receive appropriate verification; prose-only edits do not require self-mirroring tests.

## Research recommendations superseded or deferred

Keep descriptive research and add a separate evaluative rpi-assess workflow. Do not replace native phase gates with an automatic goal loop. Do not treat Claude metadata, shared symlinks, plugin availability or a zero-result validator as cross-harness proof. Do not add a model-selection service, default cloud scheduler, automatic fleet updater, arbitrary per-task token cap, mandatory skill split, or automatic xhigh research setting. Keep the small inherited/profile model approach with an explicitly selected economy option. The root instruction size budget is a packaging constraint, not a claimed universal reasoning limit.

The screenshot-intake and Copilot/OpenCode cleanup, Nothing design tuning, staged Storybook repair, Graphify source packaging, and actual adopter release/data fixes remain named external follow-ups. The v2 updater must identify and preserve them rather than claim it repaired them.
